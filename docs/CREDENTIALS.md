# Release credentials

Never send credentials in chat, commit them, print them in logs, or place them in artifacts. Base64 is encoding, not protection. Keep local values in an encrypted password manager or ignored `.env`; `.env.example` contains names only. A local Developer ID identity can remain in Keychain and does not need to be copied into `.env`.

GitHub settings are under **Repository → Settings → Secrets and variables → Actions**. Add secret material with **New repository secret** and public identifiers with **New repository variable**. The release workflow requires the Apple settings below plus this repository's Sparkle private key. Apple credentials can be shared across apps on the same Developer ID team; the Sparkle key cannot.

| Name | Purpose and type | Scope | Obtain and configure | Local use and safe verification | Backup, rotation, and loss |
| --- | --- | --- | --- | --- | --- |
| `DEVELOPER_ID_CERTIFICATE_P12_BASE64` | Secret. Encoded PKCS#12 Developer ID Application certificate and private key. | Apple Developer team; configure for this repository (or an approved organization secret). | In Keychain Access, export the Developer ID Application identity with its private key to a password-protected `.p12`. Encode the file without line breaks, then add it as a repository secret. | Locally import the `.p12` into login Keychain; the build detects its identity. `security find-identity -v -p codesigning` lists certificate names only. CI's import step checks for a Developer ID Application identity. | Keep the original `.p12` and password in encrypted backup. Rotate before expiry or revocation and update all app repositories. Losing it blocks new signed updates; installed copies still run. |
| `DEVELOPER_ID_CERTIFICATE_PASSWORD` | Secret. Password protecting the `.p12`. | Same Apple team and repository scope as the certificate. | Set the password chosen when exporting the certificate. Add it as a repository secret. | Not needed once the identity is installed in the local Keychain. A successful `make release-check` proves that CI can import and use it without showing the password. | Store separately from the `.p12`. Change it by exporting a new certificate archive and updating both secrets. Losing the password means exporting a new archive from a valid Keychain identity. |
| `CODESIGN_IDENTITY` | Optional local setting; not a secret. | Mac user/keychain. | Use the certificate's SHA-1 identity printed by `security find-identity -v -p codesigning` only when more than one Developer ID identity is installed. | The local release check selects the available Developer ID Application identity automatically. Do not add this setting to GitHub Actions. | No backup needed; it selects a certificate already in Keychain. |
| `APPLE_NOTARY_KEY_P8_BASE64` | Secret. App Store Connect API private key used by `notarytool`. | Apple team/account; can serve both apps under the same team. | In App Store Connect, create a team API key with permission to notarize, download its `.p8` once, encode it without line breaks, and add it as a repository secret. | Local `.env` only, or pass it to `make release-check` through the environment. A successful `notarytool submit` and accepted log verifies it without printing the key. | Keep the `.p8` in encrypted backup. If lost, create a replacement key, update both repos, validate it, then revoke the old key. Revocation without replacement blocks notarization. |
| `APPLE_NOTARY_KEY_ID` | Public identifier; GitHub Actions variable, not a secret. | Apple team/account; same across apps using this API key. | Copy the Key ID shown when creating the App Store Connect API key. Add as a repository variable. | May be in local `.env`. `gh variable list --repo pedrotmr/git-bar` shows configured names, not values. `make release-check` confirms that the identifier works with the private key. | Keep with the `.p8` backup. If replacing the API key, update it alongside the new `.p8`; the old identifier stops working after revocation. |
| `APPLE_NOTARY_ISSUER_ID` | Public identifier; GitHub Actions variable, not a secret. | Apple team/account; same across apps using this account. | Copy the Issuer ID from App Store Connect → Users and Access → Integrations → App Store Connect API. Add as a repository variable. | May be in local `.env`; list the variable name with `gh variable list`. A successful `notarytool submit` verifies it. | Record it with the API key details. It rarely changes; when the API key is rotated, confirm the issuer still matches the team. |
| `SPARKLE_PRIVATE_KEY` | Secret EdDSA key for signing appcast updates. Never reuse it between apps. | GitBar app only, stored in GitBar's repository secret. | After `make setup`, use Sparkle's `generate_keys --account git-bar` to create or inspect the GitBar key in Keychain. Back it up to encrypted storage without printing it. Add the exact private key as `SPARKLE_PRIVATE_KEY` in this repository's Actions secrets. For an existing key, preserve that key and verify the public key in `Config/App.xcconfig`; do not generate a replacement casually. | Local release checks can use an ignored `.env` entry or the Keychain account. `gh secret list --repo pedrotmr/git-bar` shows only its name. `make release-check` checks the appcast signature against the release ZIP. | Keep a restricted encrypted backup. Rotation needs a tested transition plan for installed apps and must change the versioned public key; losing the key prevents the current installed app from trusting future feed signatures. |
| `SPARKLE_PUBLIC_ED_KEY` | Public EdDSA key in `Config/App.xcconfig`; not a secret and not a GitHub secret. | GitBar app only. | Sparkle's `generate_keys -p --account git-bar` prints the public key. Put it in the versioned xcconfig and confirm it matches the private key used for appcast signing. | `make check` verifies it exists in the built bundle. No secret-list check is needed. | Keep the public key in source control. Update it only with a planned private-key rotation; changing it without a transition breaks updates for installed builds. |
| `SPARKLE_KEYCHAIN_ACCOUNT` | Public local setting derived from `RELEASE_SLUG`; not a secret. | GitBar's local login Keychain. | The Makefile uses `git-bar` as the Sparkle Keychain account. Do not configure it separately in GitHub. | `make release-check` checks this account when no `SPARKLE_PRIVATE_KEY` is supplied locally. | No backup needed; it is the stable lookup name for the app-specific key. |
| `GITHUB_TOKEN` | GitHub Actions built-in token; not a stored secret. | Created per repository and workflow run. | No setup. Workflows request only the contents, pull request, issue, or action permissions they use. | The workflow's `gh` commands verify access. Never copy a generated token into `.env`. | GitHub rotates it for each job. It expires automatically; no backup is needed. |

## Local configuration

Copy `.env.example` to the ignored `.env` only if the release check needs values that are not in Keychain. Put values on one line with no quotes or inline comments; keep actual values out of terminal output and version control. The release script reads only its allowlisted Apple and Sparkle settings; it does not source unrelated `.env` entries, and it removes private values from the Xcode build environment. The normal setup/build/test commands do not load or require release credentials.

Confirm GitHub configuration without revealing values:

```sh
gh secret list --repo pedrotmr/git-bar
gh variable list --repo pedrotmr/git-bar
```

As checked on 2026-10-26, GitHub lists `SPARKLE_PRIVATE_KEY` but no Apple/Developer ID secrets and no repository variables. The redundant `SPARKLE_PUBLIC_KEY` secret was removed because the public key is versioned in `Config/App.xcconfig`. The configured Sparkle private key has not yet been validated against Apple's distribution flow. The local `.env` contains blank placeholders until configured.

To configure GitHub, open **Settings → Secrets and variables → Actions**. Add `DEVELOPER_ID_CERTIFICATE_P12_BASE64`, `DEVELOPER_ID_CERTIFICATE_PASSWORD`, `APPLE_NOTARY_KEY_P8_BASE64`, and `SPARKLE_PRIVATE_KEY` in **Secrets**. Add `APPLE_NOTARY_KEY_ID` and `APPLE_NOTARY_ISSUER_ID` in **Variables**. Keep the `.p8`, exported certificate, certificate password, and Sparkle private key in encrypted storage; Base64 only changes the encoding. Never paste secret values into chat, an issue, terminal transcript, or commit. Use the Sparkle CLI's export option with shell redirection to a private temporary file, then add that file as `SPARKLE_PRIVATE_KEY`. A signed-distribution workflow run validates the settings without printing them.

The names for secrets and variables must appear in those lists. Their values remain hidden. `make release-check APP_BUILD_NUMBER=<new-increasing-number>` is the end-to-end check: it imports the signing identity in CI, contacts Apple's notarization service, and verifies the appcast signature. It creates local artifacts only.
